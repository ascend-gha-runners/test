# 架构决策记录 (ADR) — 目录规则

本目录用于沉淀 **ascend-gha-runners/test** 仓库的重大测试架构演进、方案调整、选型变更与核心机制定义。

## 写作与流转规则

1. **何时必须写 ADR**：
   - **测试方案变化**：如测试用例聚合/拆分方式、多集群调度策略重构；
   - **选型变化**：如测试驱动框架调整、包管理器/编译器选型、镜像基准升级；
   - **新增机制**：如新增响应头判定标准、跨架构兼容策略、容灾降级规则、SLA 探针分级。
2. **命名规范**：
   - 新增 `NNNN-<标题>.md`（`NNNN` 为四位递增数字，如 `0001-平台特性用例采用基础功能与用户场景双重视角闭环.md`）；
   - 同步更新 [`README.md`](README.md) 索引表。
3. **状态定义**：
   - `已接受` (Accepted)：已经团队评审并落地合入；
   - `提议中` (Proposed)：随 PR 讨论中；
   - `已取代` (Superseded)：已被后续决策取代（必须注明取代的新 ADR 编号）。
4. **决策权威性**：
   - 已决策事项不得在日常代码评审中随意推翻重开；确需变更时，必须新增 ADR 说明变更动因并在新 ADR 中声明取代旧编号。
